# Agent Teams 路由

DSH 已安装 dsh-agent-teams 插件（desktop profile）：当前会话作为队长，可拉起持久子代理成员、按依赖调度任务、成员间直接私信，Web 面板实时展示进度与任务 DAG，状态持久化在工作区 `.agent-teams/`。

本 skill 只负责一件事：**判断该不该建团队，以及如何激活**。

## 何时使用（满足任一）

- 任务可拆成 ≥2 条**互不依赖**的独立工作线（多角度审查、多模块改造、分方向调研、批量文件审计）
- 每条线的工作量足以抵消建队开销（不是几分钟能做完的小事）
- 用户明确提到"团队 / 并行 / 分头 / agent-teams"

典型模板：

| 场景 | 口令示例 |
|---|---|
| 多角度 RTL 审查 | 「用 AgentTeams 从时序风险、可综合性、接口一致性三个角度审查 <路径> 的改动」 |
| 多模块批量作业 | 「用 AgentTeams 给 <模块列表> 分别补 regmap 文档和断言，最后汇总」 |
| 并行调研 | 「用 AgentTeams 分别调研 A / B / C 三个方案，出对比报告」 |
| 交付三连 | 「实现完成后用 AgentTeams 并行：写 testbench、跑 rtl-code-review、更新文档」 |

## 何时不使用

- 单文件小改动、快问快答 —— 直接做
- 步骤强依赖（A 的结果决定 B 怎么做）—— 串行做
- 任务拆不出独立线 —— 用内置 subagent 单点委派即可

判断口诀：**能拆成互不依赖的线才建队；不能拆，团队只会更慢更贵。**

## 激活方式

1. 优先引导用户使用 slash 命令：`/agent-teams <目标描述>`（Web GUI 输入框敲 `/` 可见）
2. 或直接自然语言：「用 AgentTeams …」，插件的队长协议即生效
3. 激活后遵循插件协议：建队 → 分配角色成员 → 拆依赖任务 → 调度执行 → 汇总归档

## 模型分配规则（回答用户疑问时引用）

- 默认零交互：每个成员**快照队长当前路由**（provider + 模型 + reasoning effort），全队同模型
- 仅当用户显式要求异构（如「后端用 A 模型，前端用 B 模型」）才按成员指定 provider/model
- 成员被唤醒续跑时恢复快照配置，不随队长当前会话漂移

## 成本提醒

- N 个成员并行 ≈ token 消耗 ×N，执行前向用户确认规模可接受
- 后台成员同样消耗 API 额度；长任务建议先小范围试跑一轮

## 与其他能力的关系

- 仅需一次并行扇出、不需要团队管理界面 → 用内置 subagent / workflow 即可
- agent-teams 的增量价值：任务 DAG 可视化、成员持久化可唤醒追问、依赖调度与恢复
