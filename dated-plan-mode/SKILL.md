# Dated Plan Mode

## Trigger

When the user asks to enter plan mode (e.g. "进入planmode", "planmode", "计划模式", "进入计划模式", "开始计划模式"), activate the plan-mode workflow below.

## Workflow

1. **Enter plan mode**: Call the `EnterPlanMode` tool to start the planning phase.
2. **Official plan file**: Kimi Code internally saves the plan file to:
   ```
   C:\Users\zhuyanming\.kimi\plans\{marvel-slug}.md
   ```
   You must still write the plan to this official path so `ExitPlanMode` can read it.
3. **Local synchronized copy**: A user-configured `[[hooks]]` entry automatically mirrors the official plan file to:
   ```
   {current_work_dir}\plan\MMDD_pN_{marvel-slug}.md
   ```
   - `MMDD` is today's month and day (e.g. `0629`).
   - `pN` is an auto-incrementing index per day (`p1`, `p2`, …).
   - `{marvel-slug}` is the official Marvel-style slug generated by Kimi Code (e.g. `sentry-captain-america-nova`).
4. **Date source**: Use the current system date. If today is June 29, 2026, the local copy prefix is `0629`.
5. **Approval gate**: After writing the plan file, use the `ExitPlanMode` tool to present the plan to the user for approval before implementation.

## Important Notes

- Do **not** try to override the official plan file path. The hook handles copying/renaming.
- If the user asks where the plan is saved, mention both locations but emphasize that the local copy in `{workdir}\plan\` is the one they should use for daily reference.
- If the hook appears not to have run (no `{workdir}\plan\` directory exists), you can remind the user to restart their Kimi Code session so the updated `~/.kimi/config.toml` is loaded.
