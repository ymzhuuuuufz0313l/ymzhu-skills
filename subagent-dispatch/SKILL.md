# Subagent 派发协议（模型分工 + 确认）

派发子代理前，按下面的分工选模型，并在需要时先让用户确认，再派。
本策略针对**本桌面已授权的子代理模型**（见 DSH 设置「Subagent」页）。

> 🚫 **Kimi 不可用（2026-10-19 用户告知：套餐已过期）：K3 / Kimi For Coding HighSpeed 当前完全无法使用，任何场景都不得派发——用户点名时也先提醒套餐过期，改派 GLM。原「仅限用户特别点名」规则（2026-09-30）自套餐过期起作废，套餐恢复前 Kimi 一律不可选。**

|---|---|
| GLM-5.3 / GLM-5.3-flash / GLM-5.3-flashx | **默认主力**：已开 GLM 高级别套餐，一切派发优先 GLM 系（高强度用 GLM-5.3；快/大规模用 flash；不确定就直派继承当前路由） |
| Kimi K3（kimi-coding/k3） | 🚫 **不可用**：套餐已过期（2026-10-19 用户告知），一律不派发；点名时提醒过期并改用 GLM |

**实测事实（2026-09-29/30）**：`subagent` 支持 `provider`/`model` 跨模型覆盖（K3 / Qwen / GLM-5.3 均实测通过）。同模型同任务对比：subagent 与 agent-teams 成员产出质量相当，subagent 更快、机制更轻。**默认用 subagent，不建 agent-teams 队**（除非用户明确要求团队模式）。agent-teams 插件自桌面 0.2.0-rc.2 起全功能正常（2026-10-04 实测：建队/调度/任务板/成员执行/完成报告全链路通过），用户点名团队模式时直接用。

## 派发协议

1. **选模型**：默认 GLM 系（高强度任务 GLM-5.3；快/大规模 GLM-5.3-flash；不确定就直派继承当前路由）。
2. **Kimi 不可用（套餐已过期，2026-10-19）**：任何场景都不派 Kimi（K3/HighSpeed）；用户点名时提醒套餐过期，改派 GLM（高强度 GLM-5.3，快/大规模 GLM-5.3-flash）。
3. **交叉验证与脏活派发（由模型判断，非机械）**：派发实质工作任务时，**由你思考判断**是否需要额外派发给 Qwen——不要求每个任务都同步双派。

   **值得派发的场景（鼓励多派，不必吝啬 token）：**
   - 任务结论会作为后续决策的**唯一依据**（比如"这个 bug 的根因是什么"→ 错了全盘错）
   - 任务涉及**多文件/多模块**，单个模型容易遗漏上下文
   - 任务输出是**交付物**（文档、代码、报告）而非中间推导
   - 任务有**明确的可验证答案**（是/否、数值、具体行号），便于比对仲裁
   - 你**自己不太确定**答案，需要第二视角
   - 用户特别强调"仔细"、"重要"、"不能错"

   **不值得派发的场景（省着点）：**
   - 琐碎确认（连通性测试、一句话回答、ls 目录）
   - 纯格式转换（markdown → docx、代码格式美化）
   - 你已经非常确定答案，第二份只是走流程
   - 任务结果只是中间变量，后续步骤会自然校验

   **给 Qwen 的 prompt 规则**：256K 上下文上限，只给目标 + 文件路径，让 Qwen 自读文件，不内联大段内容。
   **比对规则**：两份结果一致则采信；不一致则比对分歧点，你仲裁或呈报用户。
4. **需要确认时**（多子代理 / 严谨模式 / 要覆盖默认模型）：把「任务 → 模型」列给用户确认后再派。
5. **单个简单子代理**：按档直派，不逐次打断。
6. **收尾**：一次性子代理拿回结果即弃；要留给其他会话 / agent 的结论，**显式存进 dsh-mnemon**（Document / 记忆），别指望子代理记得。
