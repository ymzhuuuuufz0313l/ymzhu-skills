## 2. 目录结构

本目录常见组织方式：

```
{PROJECT_NAME}/
├── AGENTS.md                  # 本项目上下文与 Agent 工作规则（本文件）
├── CHANGES.md                 # 变更日志
├── REVIEW.md                  # 服务器回传前检查清单（临时）
├── file_list/                 # 仿真/综合文件列表（*.f）
│   ├── {project}.f
│   ├── {project}_digital_top.f
│   └── macro.f
├── {project}_digital_top/     # 数字顶层（如 HK1V11_digital_top）
├── STD_IP/                    # 标准 IP
├── TOP/                       # 顶层封装
├── clk_rst/                   # 时钟复位相关
├── code_comment/              # 代码注释/说明
├── module_mk/                 # 模块 make 脚本
├── spg/                       # 特殊功能模块
├── *.v / *.sv                 # 扁平化放置的 RTL 源文件
├── check_report.md            # 寄存器/代码检查报告
└── README.md                  # 本目录简介
```

实际结构可能为以上两种风格的组合：
- **分层组织**：按功能/层次分目录（如 HK1V11/HDL）
- **扁平组织**：所有 `.v` 文件直接放在根目录（如 HV2M23/hdl）

## 3. AI 必须遵守的规则

### 3.1 通用规则

1. **先读上下文**：每次对话开始时，先读取本目录中的 `AGENTS.md` 和 `CHANGES.md`。
2. **只改代码，不跑仿真**：本项目不在本地运行 case 仿真。AI 修改代码后，重点进行代码可靠性检查（语法、风格、接口一致性、时序影响分析）。
3. **严格记录变更**：每次文件修改必须记录到 `CHANGES.md`，包括文件路径、修改类型、行号范围、修改摘要。
4. **服务器回传前 review**：当用户要求"准备回传服务器"时，生成 `REVIEW.md`，列出所有变更、关联文件和肉眼检查建议。
5. **禁止行为**：未经用户同意，不得删除、重命名或移动 `AGENTS.md`、`CHANGES.md` 文件。
6. **完成汇报**：每次修改后，向用户简要说明变更摘要。

### 3.2 RTL 修改规则

1. **RTL 风格一致**：遵循项目已有命名规范、 always 块写法、复位策略、时钟门控风格。
2. **Filelist 同步**：
   - 新增/删除/重命名 `.v` / `.sv` 文件 → 同步更新 `file_list/*.f`
   - 修改宏定义 → 同步更新 `macro*.f`
3. **接口变更同步**：
   - 新增/删除端口信号 → 更新本文件"接口说明"章节，并同步更新上层实例化
   - 修改位宽/极性 → 更新接口说明和寄存器文档
   - 修改状态机 → 更新状态转换说明或状态机图
4. **寄存器维护**：
   - 修改寄存器地址/位域/默认值 → 更新寄存器表（如 `HK1V11_Register_*.xlsx` / `.md`）
   - 修改寄存器读写逻辑 → 更新 `check_report.md` 或等效验证报告
5. **修改记录**：重大修改应同步到项目 `修改记录` 或 `changelist` 文档。

## 9. 常见任务

- 查看文件列表：`cat file_list/{project}.f`
- 查看变更日志：`cat CHANGES.md`
- 生成回传清单：`@workflow-maintainer 准备回传服务器`
- 语法检查：`vlogan -f file_list/{project}.f` 或 `iverilog -g2012 -f file_list/{project}.f`
- 综合检查：`make syn` 或 `dc_shell -f run_dc.tcl`
- 查看 rtl 规模：`find . -name "*.v" -o -name "*.sv" | wc -l`
- 查看寄存器报告：`cat check_report.md`
