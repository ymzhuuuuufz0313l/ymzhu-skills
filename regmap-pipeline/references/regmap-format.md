# regmap.md 格式定义

`generate_regmap_doc.py` / `generate_regmap_assertions.py` 解析的 `regmap.md` 格式。每个模块一份 `regmap.md`，作为该模块寄存器的单一事实源。

## 1. 寄存器总表（必需）

章节标题必须是 `## 1. 寄存器列表` 或 `## 1. Register List`，内含如下表格：

```markdown
## 1. 寄存器列表

| 寄存器名 | 地址偏移 | 位宽 | 访问类型 | 复位值 | REQ_ID | 功能描述 |
| --- | --- | --- | --- | --- | --- | --- |
| CTRL | 0x00 | 32 | RW | 0x0000_0001 | REQ-M01-R001 | 控制寄存器 |
| STATUS | 0x04 | 32 | RO | 0x0000_0000 | REQ-M01-R002 | 状态寄存器 |
```

列约束：

| 列 | 格式 |
| --- | --- |
| 寄存器名 | 标识符（`\w+`），与 RTL 中命名一致 |
| 地址偏移 | `0x` 前缀十六进制，可用 `_` 分隔（如 `0x0000_0001`） |
| 位宽 | 十进制整数 |
| 访问类型 | `RO` / `WO` / `RW` / `W1C`（大小写不敏感，内部统一转大写） |
| 复位值 | `0x` 前缀十六进制，可用 `_` 分隔 |
| REQ_ID | 需求追溯号（无追溯体系时可填占位符，但列不能省） |
| 功能描述 | 自由文本 |

## 2. 位域定义（生成位级断言时需要）

每个寄存器一个小节，标题格式 `### 2.<n> <寄存器名> (0x<地址>)`，内含 `#### 位域定义` 表格：

```markdown
### 2.1 CTRL (0x00) - 控制寄存器

#### 位域定义

| 位 | 名称 | 访问 | 复位值 | 功能 |
| --- | --- | --- | --- | --- |
| [0] | enable | RW | 0x1 | 模块使能 |
| [7:4] | mode | RW | 0x0 | 工作模式 |
| [31:8] | reserved | RO | 0x0 | 保留位 |
```

列约束：

- **位**：`[n]` 单bit 或 `[high:low]` 区间
- **访问**：同总表访问类型
- **复位值**：`0x` hex 或十进制
- `reserved` 字段用于生成 reserved 位断言

## 解析行为备注

- 两个脚本都用正则按上述结构解析；**章节编号（`## 1.`、`### 2.x`）和表头必须严格匹配**，否则静默解析为空。
- 解析结果为空时脚本不会报错退出，只会生成空产物——生成后务必检查产物内容是否非空、寄存器数量是否符合预期。
