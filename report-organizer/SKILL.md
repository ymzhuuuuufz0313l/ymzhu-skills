# Report Organizer Skill

## Trigger

当用户要求整理/生成报告，并将报告放入 `E:/report` 时触发，例如：
- "整理报告"
- "报告移入网站"
- "生成一份 XX 报告"
- "创建报告到 E:/report"
- "整理 markdown 报告"
- "把这段内容整理成报告"

如果用户没有指定报告目录或主题，主动询问。

## 核心目标

整理报告时，**不要写流水账**，要提取精华、突出重点、强调可视化。报告最终是给读者快速理解用的，不是原始材料的堆叠。

## Workflow

### 步骤 1：明确报告主题与范围

1. 从对话中提取或询问：
   - 报告主题/标题
   - 报告类型（功能设计、问题分析、测试验证、项目复盘、方案对比等）
   - 来源材料（聊天记录、代码改动、已有 Markdown、图片、截图等）
   - 目标读者是谁
2. 确定核心结论：读者看完这份报告应该记住哪 3-5 个点？

### 步骤 2：创建报告目录

在 `E:/report/` 下创建报告目录，目录名即报告名：

```
E:/report/<report_name>/
├── <report_name>.md    # 报告源文件，文件名与目录同名
└── assets/              # 图片、流程图、框图、波形截图等（可选但强烈建议）
```

目录命名建议：
- 与报告主题一致，使用英文或拼音。
- 避免空格和特殊字符。
- 例如：`HK1V11_longcode_420b_summary`、`DRDOD_function_report`。

**注意**：报告源文件必须叫 `<report_name>.md`，不要命名为 `README.md`。

### 步骤 3：提取精华并编写报告

编写原则：

1. **结论先行**：每个章节先给结论、图表或总览表，再展开说明。
2. **少即是多**：删除无关细节，只保留支撑结论的关键信息。
3. **可视化优先**：能用图就不用纯文字，能用表格就不用大段描述。
4. **一页一扫而过**：每个 `##` 大类应该让读者在 30 秒内抓住重点。

推荐内容结构：

```markdown
# 报告标题

## 1. 一页总览
- 核心结论、关键数据、状态分布。
- 优先用总览表 + 状态图/架构图。

## 2. 背景与目标
- 为什么要做这件事？目标是什么？
- 用简短段落 + 流程图说明。

## 3. 关键分析
- 分 2-4 个小节，每节一个核心观点。
- 每个观点配：结论句 + 表格/对比图 + 关键数据。

## 4. 验证/结果
- 测试覆盖、case 结果、关键指标。
- 用结果表 + 趋势图/对比图呈现。

## 5. 风险与下一步
- 未关闭问题、风险、后续动作。
- 用风险矩阵表或待办列表。
```

### 步骤 4：强化可视化

报告必须包含可视化元素，避免纯文本堆砌：

1. **Mermaid 流程图/架构图**：
   ```markdown
   ```mermaid
   flowchart LR
     A[输入] --> B[处理]
     B --> C[输出]
   ```
   ```

2. **对比表格**：
   - 方案对比、版本对比、Before/After 对比。
   - 突出差异列，避免只有描述没有数据。

3. **状态/优先级矩阵**：
   - 用表格或二维图展示问题状态、优先级、负责人。

4. **截图/波形/框图**：
   - 保存到 `assets/`，在 Markdown 中引用：`![描述](assets/xxx.png)`。

5. **关键数字突出**：
   - 用表格或加粗列出关键指标，不要藏在段落里。

### 步骤 5：格式自检

- [ ] Markdown 文件名与目录同名。
- [ ] 每个 `##` 大类有明确结论或可视化元素。
- [ ] 表格语法标准，有表头分隔行。
- [ ] 状态/结果字段使用固定枚举：`PASS`、`FAIL`、`TBD`、`NA`、`PARTIAL`。
- [ ] 提示块前缀规范：`NOTE:`、`ASSUMPTION:`、`RISK:`、`TODO:`、`RESULT:`、`RESULT(FAIL):`。
- [ ] 信号名、文件名、case 名使用反引号。
- [ ] 图片路径指向 `assets/` 子目录。
- [ ] 删除冗余描述，保留精华。

### 步骤 6：汇报结果

向用户汇报：
- 报告目录和 Markdown 文件路径。
- 主要结构（2-3 句话）。
- 包含的可视化元素（图、表、流程图等）。
- 任何待补项或风险（如 `TODO:` 引用块）。

## Format Rules（必须遵守）

1. **Markdown 是唯一可维护源文件**。
2. **文件名与目录同名**，不使用 `README.md`。
3. **结论先行**：每个章节先给核心结论，再补充细节。
4. **可视化优先**：每份报告至少包含 1 个图或流程图，每个 `##` 大类尽量有表格。
5. **提取精华**：删除原始材料中的流水账、重复描述和无关细节。
6. **状态字段使用固定枚举**：`PASS`、`FAIL`、`TBD`、`NA`、`PARTIAL`。
7. **提示块前缀规范**：`NOTE:`、`ASSUMPTION:`、`RISK:`、`TODO:`、`RESULT:`、`RESULT(FAIL):`。
8. **图片统一放 `assets/`** 子目录，Markdown 中相对引用。

## Output Format

完成报告整理后，按以下格式汇报：

```markdown
已整理报告：

- 报告目录：`<report_name>/`
- Markdown 源文件：`<report_name>/<report_name>.md`
- 主要结构：一页总览、背景与目标、关键分析、验证/结果、风险与下一步
- 可视化元素：{列出图、表、流程图等}
- 待补项：{列出 TODO 引用块，如有}
```
